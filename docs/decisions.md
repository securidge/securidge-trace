# 결정 기록

KM의 지시(2026.11.21.)에 따라 Phase 0 보고서의 결정 사항을 개발 쪽에서 판단해 정했다.
바꾸려면 이 문서를 고치고 영향받는 단계를 다시 계획한다.

| # | 결정 | 이유 | 다시 볼 시점 |
|---|---|---|---|
| D1 | 화면은 **egui/eframe**으로 간다 | 실행 파일 하나로 배포 가능, MIT/Apache, 고지 의무 없음. 한글 표시는 맑은 고딕을 불러와 해결 | Windows에서 한글 입력기 조합 입력을 시험해 실패하면 Slint로 바꾼다 (GitHub 가상 머신은 화면 입력 시험이 안 되므로 사람이 한 번 확인해야 함) |
| D2 | 잠긴 파일은 **볼륨을 읽기 전용으로 직접 읽어 NTFS를 해석**한다 | 대상 PC에 쓰기가 없다. VSS는 스냅샷이라는 흔적을 남긴다 | 백신·EDR 오탐이 심하면 재검토 |
| D3 | 코드 서명 인증서는 **지금 사지 않는다** | 비용이 들고, 사도 초기에는 경고가 뜬다. 한국에서는 Microsoft 서명 서비스를 쓸 수 없다 | 실제 고객사 배포 직전 |
| D4 | 제품명 **Securidge Trace**, 저장소 `securidge/securidge-trace` (비공개) | KM 지시 | - |
| D5 | 지난 내역 **암호 보호는 필수 기능**으로 올린다 (Phase 5) | 여러 고객사 직원의 기록이 USB 하나에 쌓이고, 분실 시 유출 사고가 된다 | - |
| D6 | 수집본(원본 사본) 보관은 **기본 꺼짐**, 대신 **수집 목록(manifest: 경로·원래 시각·크기·해시)은 항상 저장** | 개인정보 최소화. 목록이 있으면 "무엇을 근거로 했는지"는 남는다 | 재분석 요구가 생기면 "암호화된 수집본 보관" 옵션 추가 |

## 검증 환경

- 이 개발 환경(Linux 컨테이너)에는 가상화 기능이 없어 Windows 가상 머신을 직접 띄울 수 없다.
- 대신 **GitHub Actions의 Windows 가상 머신(Windows Server 2022, 2025)**에서 실제 기록을 만들고 정답과 대조한다 (`ci/win-setup-truth.ps1`, `ci/verify_truth.py`).
- 이 방식의 한계: 실제 USB를 꽂을 수 없고(VHD는 고정 디스크로 보임), 클라이언트 Windows 10/11이 아니며, 화면을 사람처럼 조작할 수 없다. 이 세 가지는 사람이 한 번은 실제 PC에서 확인해야 한다.
