## 검증 환경

- 이 개발 환경(Linux 컨테이너)에는 가상화 기능이 없어 Windows 가상 머신을 직접 띄울 수 없다.
- 대신 **GitHub Actions의 Windows 가상 머신(Windows Server 2022, 2025)**에서 실제 기록을 만들고 정답과 대조한다 (`ci/win-setup-truth.ps1`, `ci/verify_truth.py`).
- 이 방식의 한계: 실제 USB를 꽂을 수 없고(VHD는 고정 디스크로 보임), 클라이언트 Windows 10/11이 아니며, 화면을 사람처럼 조작할 수 없다. 이 세 가지는 사람이 한 번은 실제 PC에서 확인해야 한다.

## 실기 검증에서 알게 된 것 (2026.11.21.)

- Windows Server 2022·2025에서 `SHAddToRecentDocs`는 Recent 폴더에 **확장자를 뺀 이름**(`memo_test.txt` → `memo_test.lnk`)으로 몇 초 뒤에 바로 가기를 만든다. 파일 이름이 같고 확장자만 다른 두 파일은 바로 가기 하나를 같이 쓸 수 있으므로, 상관 분석(Phase 4)에서 "바로 가기 이름 = 파일 이름"으로 가정하면 안 된다. 대상 경로는 바로 가기 안의 값만 믿는다.
- 같은 파일을 가리키는 바로 가기가 여러 개 있을 수 있다. 각각은 별개의 사실로 남기고, 묶는 일은 상관 분석에서 한다.
- 같은 시점에 `AutomaticDestinations`(Jump List)도 갱신된다. Phase 2의 Jump List 파서 검증에 쓸 수 있다.
- 헤드리스 Chrome·Edge를 25초 실행하고 강제 종료하면 방문 기록이 남지 않았다. 브라우저 실기 검증은 정상 종료 방식으로 다시 설계해야 한다.
- GitHub 가상 머신의 시간대는 UTC다. 로컬 시간으로 저장되는 기록(NetworkList 등)의 변환 검증에는 시간대를 바꿔 시험해야 한다.

## 구현 중 추가로 정한 것 (2026.11.21.)

| 항목 | 결정 | 이유 |
|---|---|---|
| 컴파일러 | Rust **1.97.0 고정** (`rust-toolchain.toml`, CI) | CI의 최신 컴파일러(1.100)에서 새 린트가 추가돼 빌드가 깨졌다. 배포물 재현성을 위해 고정 |
| notatin의 nom 의존성 | `Cargo.lock`에서 **nom 7.1.3** 고정 | notatin 1.0.1이 `nom >= 6`으로 열려 있어 nom 8이 잡히면 컴파일되지 않는다 |
| 판단 규칙 정의 방식 | 규칙 8개(R1~R8)는 코드로, **켜기·끄기와 기준값·주소 분류표는 설정 파일**로 | 개발 요청서는 "규칙을 외부 파일로"였으나, 비전문가가 조건식을 고칠 일이 없고 오류 위험이 커서 기준값만 열어 둠 |
| 시각 변경 규칙(R6) | **사람 계정(S-1-5-21-…)이 10분 이상** 바꾼 경우만 | 공개 샘플에서 Windows 시간 동기화·VMware Tools(시스템 계정)가 시각 변경 기록을 매우 자주 남겼다 |
| 등급 | 참고(Low) 판단만 있으면 등급을 올리지 않는다. SYSTEM 하이브를 못 읽으면 '판단 불가' | 오탐으로 사람을 의심하게 만들지 않기 위함 |
| 화면 렌더링 | eframe 기본(wgpu: Windows에서 DirectX 12, 그래픽 장치가 없으면 소프트웨어 WARP) | OpenGL만 쓰면 원격 데스크톱·가상 머신에서 실패하는 경우가 많다 |
| 권한 상승 | 실행 파일 매니페스트 `highestAvailable` | 관리자 계정이면 실행 즉시 권한 상승을 묻고, 일반 계정이면 제한 점검으로 실행된다 |
| 지난 내역 암호 보호(D5) | **v0.1에는 미구현** | 범위가 커서 다음 버전으로 미룸. README·안내문에 "USB 분실 주의"를 명시 |
